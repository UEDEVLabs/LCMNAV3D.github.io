Settings Reference: LcmNavigationManagerSVO

Applies to LCM Nav3D 3.6.0 · Unreal Engine 5.2 to 5.8 · Updated 22 November 2026

This page lists every field on the navigation manager, in the same order as the Details panel. The defaults and limits are the values the plugin ships with.

The four most important settings are Infinite World, World Extent / Chunk Size, Min Voxel Size and Clearance Padding. Get these right first. The others are for fine-tuning.

The ideas behind these settings are explained in Tutorial 02: Core Concepts.

The panel at a glance

The manager's Details panel starts with an LCM Nav3D group above the usual Actor sections, followed by seven numbered sections in the order below.

Figure 1: Sections 1-2, and the three blocks above them. Configuration Health and What You Get are not settings. They show what the settings below produce, so read them before you change anything. In this screenshot the health block reports that the invoker radius was raised, and What You Get shows a 250 cm finest leaf from a 100 cm Min Voxel Size. People often misread that second number.

Figure 2: Sections 3-7. Two things to know:

  • Section 7 is read-only. Each (auto) row is a value the Streaming Profile chose, shown so you can see it. Frontier Stall Recovery (auto) is the only place you can see what a Behavior Tree task's Inherit turns into, because a BT asset doesn't belong to a level and doesn't know which manager it will run under.
  • Settings that don't apply are hidden. A finite world shows no Coarse Skeleton options, and Max Generations Per Frame is only shown in a finite world or with the Manual profile. If a setting would be ignored, it isn't shown.

1. Setup

Infinite World: default off

This is the most important choice. Off means one fixed navigation volume, built at the start. On means the world is split into chunks, which are built around agents as they move.

Leave it off unless your world really is unbounded or streamed. Finite is simpler, faster and more predictable.

Ticking it hides World Extent and shows Chunk Size and the skeleton options instead.

Levels that stream in late. If a streaming level loads after the navigation around it was built, the chunks it overlaps are rebuilt automatically, so its geometry is added to the navigation. Three console variables control this:

Console variable Default Meaning
r.LcmNav.Streaming.RevoxelizeOnLevelStreamIn 1 Rebuild the chunks a newly streamed level overlaps. 0 turns it off
r.LcmNav.Streaming.RevoxelizeGraceSeconds 2 Chunks built within this many seconds after the level arrived are rebuilt too
r.LcmNav.Streaming.RevoxelizeMaxPerTick 8 Most chunks released for rebuild per frame, so the work is spread out

Auto Build On Play: default on (finite only)

Builds the navigation volume at BeginPlay. This voxelizes the whole world every time the game starts, on every player's machine. Turn it off if you call BuildSVO yourself from Blueprint, or if you have baked the octree to an asset.

Turn it off when you bake. The Bake to Asset button does this for you. If both were on, the streaming proxy and the manager would both write the navigation data during BeginPlay, in no fixed order, and you couldn't tell which one the level used. Configuration Health warns you about this.

Generation Strategy: read-only (infinite only)

Shows which streaming strategy the plugin picked.

2. Voxels

World Extent: default 10000 cm (finite only)

Half the width of the navigation volume, measured from the world origin. The default gives a 200 m cube, from -10000 to +10000 on each axis.

Range: 500-400000. Recommended UI range (slider): 2000-20000.

There is no navigation data outside this box, so paths to targets outside it fail. Make it big enough to cover your play space.

How big can it be? That depends on Min Voxel Size. The real limit is the number of voxels. The world is 2 × World Extent wide and holds (2 × World Extent / Min Voxel Size)³ voxels, and the limit is 64 M (400³). So the largest World Extent you can use is 200 × Min Voxel Size:

Min Voxel Size Largest World Extent World size
50 cm 10 000 200 m cube
100 cm (default) 20 000 400 m cube
200 cm 40 000 800 m cube
500 cm 100 000 2 km cube

The field used to stop at 20000. That is only right for the default Min Voxel Size: it blocked a valid 40 000 at 200 cm voxels, and allowed 8× too much at 50 cm. The field's own limit is now just an upper bound, and Configuration Health shows the real budget for your Min Voxel Size as you edit. Going over the budget doesn't cause an error. The build quietly makes Min Voxel Size coarser until it fits, so you get less detail than you asked for.

Using bigger voxels to cover a bigger area is a fair trade. A 2 km arena for flying combat at 500 cm voxels is a sensible setup, as long as you choose it on purpose.

Note: the volume does not follow the manager actor. The manager has no root component, so its position is ignored, and moving it doesn't move the navigation volume. Build your level around the world origin, or switch to an infinite world. The manager's Details panel shows the actual bounds under What You Get.

Chunk Size: default 8000 cm (infinite only)

The length of one side of a streaming chunk.

Range: 1000-800000. Recommended UI range (slider): 3000-8000. As with World Extent, the field's limit is only an upper bound; the real budget depends on Min Voxel Size and is shown in Configuration Health. Stay within the slider range. Those values worked reliably in testing, and values outside it make long-range routing worse, whatever the budget.

Note: be careful when changing this. It affects memory, build time, and whether long routes can be found at all. 8000 is the tested default. If you change it, test long routes again. A value that works for short trips can break long ones.

Smaller chunks don't always mean finer navigation

This surprises a lot of people. The octree starts at Chunk Size / 2 and keeps halving until the next half would be smaller than Min Voxel Size. So the finest leaf you get is Chunk Size / 2ᵏ. It lands somewhere between 2× and 4× Min Voxel Size, and it does not get finer just because Chunk Size gets smaller. These are the values on a real level at Min Voxel Size = 100:

Chunk Size finest leaf edge Chunk Size finest leaf edge
3000 375 cm (3.75×) 7000 219 cm (2.19×)
5000 312 cm (3.12×) 8000 250 cm (2.50×)
6000 234 cm 9000 281 cm

So a smaller Chunk Size can give you a coarser octree. At Chunk Size 3000 you get 375 cm leaves from a 100 cm setting, and an opening that is open at 250 cm can close at 375 cm. You see that as an agent that won't find a path, and it looks like a bug even though it comes from a setting.

What to do: leave it at 8000 unless testing shows you need something else. If you do change it, use the Auto-Tuner (Editor Tools). It builds the octree for each candidate and measures the leaf size, and it checks that your routes can be planned before it compares quality or cost.

Min Voxel Size: default 100 cm

The smallest size the octree will subdivide to. This setting has the biggest effect on quality and cost.

Range: 10-2000. Recommended UI range: 25-500.

  • Smaller: finds tighter gaps, but uses more memory and takes longer to build.
  • Larger: cheaper, but narrow openings disappear.

Rule of thumb: use about half the narrowest gap your agents must fly through.

This is a lower limit, not an exact size. The octree halves down from the world or chunk size, so the real size jumps in powers of two. Going from 100 to 90 may change nothing, and going from 100 to 60 may double the memory. Test your changes.

World Scale: default Standard

Sets which group of built-in centimetre values the manager uses. Standard is tuned for metre-scale worlds at a 100 cm leaf, and works exactly like earlier releases. Small works these values out from the finest leaf this manager produces. Clearance Padding becomes half the leaf (it is written into the field, which becomes read-only), and a few internal distances scale with it, so a centimetre-scale world, such as a 120 × 70 × 40 cm aquarium at 1 cm voxels, gets sensible defaults. Custom keeps whatever you set. Under Small, the padding is worked out again when you change Min Voxel Size, World Extent or Chunk Size, and again at BeginPlay, so setups that come from config files match the editor.

Min Voxel Size now goes down to 0.5 cm and World Extent down to 50 cm. The finest leaf is 2-4× Min Voxel Size, so set half the leaf you want, and make the world size a power-of-two multiple of it. In a world less than about 32 leaves across, memory grows quickly as the leaf gets smaller, and the panel tells you so. See Small Worlds.

A few internal distances in the builder and the path solver scale with the finest leaf on every profile. They keep their usual values at normal leaf sizes, and there is nothing for you to set.

Padding Mode: default Centimetres

Sets how Clearance Padding is given. Centimetres uses the value you type. Leaves sets it to Clearance Padding Leaves × the finest leaf whenever the leaf changes (and again at BeginPlay), so the padding around every surface is always the same number of leaves thick. That keeps memory growth to about 4× each time you halve the leaf. World Scale = Small already uses half a leaf, and it takes priority.

Clearance Padding Leaves: default 0.5

The number of leaves used when Padding Mode = Leaves. 0.5 grows every surface by half a leaf, the same as Small. Range: 0-4.

Clearance Padding: default 100 cm

Grows obstacles during voxelization, so agents keep clear of surfaces.

Range: 0-1000. Recommended UI range: 0-300.

Note: keep this well below Min Voxel Size. When the padding gets close to the voxel size, doorways and corridors fill in, and the pathfinder reports no route through openings you can clearly see. This is the most common reason for "it says there's no path but I can see the gap".

Coarse Cell Size: default 2500 cm

The cell size of the coarse layer used to plan long routes. Larger cells make long-range planning cheaper but less precise. The default suits most levels.

Range: 100-20000.

3. Collision

Obstacle Query Channels

The collision channels that count as obstacles. Anything on these channels is voxelized as solid. The default is WorldStatic and WorldDynamic.

An empty list means no obstacles at all. This is the opposite of Allowed Obstacle Classes below. With no channels, the whole world is voxelized as open air. Nothing warns you; you only notice when agents fly through walls. That is why Bake to Asset won't run with an empty list.

If a wall doesn't block agents, check that its collision channel is in this list and that the mesh has collision turned on.

Moving obstacles are usually WorldDynamic. If a mover's object type isn't in this list, it is never added to the octree, and Draw Debug Volumes shows the level without it.

Allowed Obstacle Classes

An optional filter. Leave it empty to include all actors, which is the normal setting. Add classes to voxelize only those actor classes, for example to ignore scenery.

4. Performance

Voxelization Method: default Auto

Where the octree is built. Auto builds it on the GPU, which is much faster, after testing this machine's GPU. There is a capability check, a self-test through the real pipeline (run once per GPU, driver and build, then remembered), and spot checks of the chunks it builds while the game runs. If the GPU fails any of them, the rest of the session voxelizes on the CPU. The log says which check failed and why, and the manager's On Voxelization Changed event fires. GPU always builds on the GPU, and CPU always builds on the CPU. Only choose CPU when you need builds that are exactly the same every time.

Levels saved with the older Use GPU Voxelization checkbox are converted to this setting when they load.

Max Generations Per Frame: default 1

How many chunks can be built per frame. A higher value fills the world faster but can cause hitches. Range: 1+, UI up to 8.

Max Path Requests Per Frame: default 64

How many path requests are handled per frame. Raise it when many agents replan at once, or lower it to protect the frame rate. Range: 1-256.

Max Requests Per Frame: default 50

A general limit on requests per frame. Range: 1-200.

Max Flow Solves Per Frame: default 4

How many flow fields can be solved per frame. Range: 0-16.

Finite Obstacle Update Interval: default 0.1 s (finite only)

How often changes from dynamic obstacles are written into the octree. A lower value reacts faster but uses more CPU. Range: 0-2 s. See Tutorial 05.

Chunk Quantized Macro Cache: default off

Caches long routes, rounded to chunk borders. This helps when many agents take similar long routes, for example a large crowd that spawns together.

Pawn Agents (BT & StateTree) subcategory

Field Default Meaning
Use Flow Fields (pawn agents only) off Opt-in: pawn agents heading to a shared goal use one steering field instead of individual paths
Flow Field Threshold 16 Agent count at which a shared field is built (range 2-512)
Flow Field Cluster Cell Size 1000 cm Grouping granularity for shared goals (range 100-10000)

Flow fields are for many agents going to the same place. For a few agents with their own goals they only add cost, so leave this off.

5. Coarse Skeleton (optional)

Two options, which you can use separately or together, that help agents plan long routes in a streamed world. Both are off by default. Only turn one on when an agent has to plan a route to a place that isn't loaded. Agents that stay inside the area around them don't need either.

Persistent Skeleton (runtime, no bake): default off (infinite only)

Keeps a small map of how the world connects in memory, so long routes can be planned before the detailed chunks exist. It needs no bake and works in any world, including procedural ones.

Turn it on when an agent comes back over ground it has already flown across and must still be able to plan routes there. It uses more memory the more ground has been covered: one small node for each chunk that was visited and then unloaded, up to r.LcmNav.MaxSkeletonNodes.

Use Baked Skeleton (frame-0 completeness): default off (infinite only)

Loads a baked skeleton, so long routes can be planned from the very first frame, including into places no agent has visited.

Tick this first. The Bake Skeleton button only appears in the banner once it is on, because nothing else uses the bake. Then click the button. Bake again after you change the level or the voxel settings. An out-of-date bake is not loaded, and the Baked Skeleton (auto) line under 7. Runtime State tells you so.

Baked Skeleton (auto) under 7. Runtime State shows which of the two is in use, if either.

6. Debug

Draw Debug Volumes: default off

Draws the octree. Use this first when something looks wrong. If a gap has no small voxels in it, the pathfinder can't use it either. It is slow to draw, so turn it off when you're done.

You can also turn it on from Blueprint with SetDrawDebugVolumes or ToggleDrawDebugVolumes.

Draw Pathfinding Debug: default off

Draws computed paths.

Draw Infinite World Debug: default off (infinite only)

Draws chunk boundaries and streaming state.

Debug Redraw Coalesce Seconds: default 0.25 s

How long debug redraws are collected before drawing. Raise it if the debug drawing slows the frame rate.

Cost Areas subcategory

Field Default Meaning
Cost View Off Draws the cost areas while playing. Regions: each volume and what it costs. Heat: the octree tinted by price. The console variable r.LcmNav.CostView 0/1/2 overrides it; -1 hands control back
Cost View Filter none Which agent's filter the view uses: a stock Navigation Query Filter class. Empty = each area's own defaults

See Tutorial 10 for cost areas themselves.

Force Redraw SVO has been removed. It was a checkbox that unticked itself straight away, and on a level with no baked data it deleted the editor preview it was meant to refresh. The preview now reloads by itself when you bake. To reload it by hand, use the Refresh Preview button, which appears on the manager when the level has baked navigation.

7. Runtime State

Read-only information: how many chunks are loaded, the skeleton state, and whether bakes are out of date. It is useful when tuning an infinite world. There is nothing to set here.

Per-agent settings

These settings are on the Fly To Behavior Tree task and the Fly To StateTree task, not on the manager. Both tasks have the same settings, in six numbered sections:

1. Goal

Field Default Meaning
Acceptance Radius 100 cm Distance at which the goal counts as reached
Target Location - (StateTree only) world-space goal
Target Actor none (StateTree only) moving goal; overrides Target Location when chase is on
Timeout Seconds 0 (no limit) (advanced) Report Failed after this long in flight. For a goal that keeps moving away, or one reached only by a very long route

2. Movement

Field Default Shown when Meaning
Agent Scale 0 (= World Scale) always Multiplies every centimetre and speed value on the task (acceptance radius, speed, acceleration, deceleration distance, wall check, separation, drift replan, Minimum Agent Size and the follower's internal floors). 0 follows the manager's World Scale: 1 under Standard, finest leaf / 100 cm under Small (0.01 in a 1 cm world). A driving flight component adopts the same scale unless its own Agent Scale is set
Use Flight Movement Component off always Delegate the body to a ULcmFlightMovementComponent for 6-DOF drone / bird / fish dynamics
Flight Speed 600 cm/s not delegating Cruise speed
Max Acceleration 2000 cm/s² not delegating Lower = heavier feel; also sets how hard the agent can brake into its arrival
Flight Style Physics (Drones/Ships) not delegating vs Linear (Biological/Magic)
Deceleration Distance 800 cm not delegating and Physics-weighted Slow-down lead-in. LinearDirect has no inertia to bleed off, and the flight component brakes on v = sqrt(2·a·d) against the real goal distance instead
Banking Amount 4.0 not delegating Roll into turns (cosmetic)
Max Banking Angle 45° not delegating Roll limit (cosmetic)

Speed and handling are set in one place. When you tick Use Flight Movement Component, this section shrinks to that one checkbox. Speed, acceleration, flight style and banking then come from the component's Flight Config, and the task reads them from there. When it is unticked, the task's own values are used.

Query Options > Require Complete Path off (advanced) Fail a request whose route stops short of the goal, instead of returning the part that can be planned now

6. Streaming (infinite worlds only)

Field Default Meaning
Frontier Stall Recovery Inherit Coast / climb out / arrive un-quantized when stalled at a streaming frontier. Inherit defers to the manager's Streaming Profile

Frontier Stall Recovery only controls how the agent moves. Loading chunks ahead of the agent is a separate setting for the whole world: Agent Corridor Prefetch on the LCM Nav3D Manager. These used to be one checkbox.

Solver and smoothing choices are described in Tutorial 02 §6.

StateTree tasks that finish at once. On UE 5.2, when one task finishes, its whole state finishes, so a FlyTo in the same state stops too. Find Cover, Chunk Prewarm, Streaming Aware, Find Actor By Tag and Pick Random Goal have a Stay Running After Resolve option. Tick it when the task shares a state with a FlyTo, and the state keeps running until the FlyTo finishes.
